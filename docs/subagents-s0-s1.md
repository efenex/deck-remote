# Read-only child summaries (S0 + S1)

Implemented provider: Claude JSONL 2.1, using the redacted 2.1.322 structural evidence in `testdata/subagents/claude-2.1`. The fixture manifest schema records provenance and unsupported formats. The response schema is `testdata/subagents/summary.schema.json`. Mutation scenarios in tests are synthetic acceptance cases, not additional captured provider versions.

OpenCode target is **2.x** (owner reports griffin 2.0.22). `capabilities.subagents` reports `summary:false`, `thread:false`, `live:false`, provider `opencode-2`, with an evidence-gate reason. No OpenCode adapter, root binding filter, parent history projection or delivery controls changed. No 1.x adapter was added.

## Contract

`subagentReader` is optional beside `harnessAdapter`. A child is a durable conversation, and its `invocations` contain distinct native parent message/tool/block anchors. Resuming a child does not increment the unique child count. Monitor and background Bash task IDs are not child IDs. Legacy Task/progress decoding is withheld pending versioned evidence.

Authenticated read-only `GET /api/rc/subagents?id=<exact Deck root>&segment=<opaque>&limit=50&cursor=<opaque>` returns schema `deck-remote.subagents/v1`. The current native segment is the only supported segment. Invalid/expired segments or cursors produce HTTP 409 with `reset:true`; the client must fetch the current first page. No child-history route is implemented. Caller-supplied child IDs, paths, URLs or host overrides are rejected.

The response embeds a bounded flat summary (`running`, `waiting`, `unknown`, `observedAt`, `freshUntil`, `availability`, `complete`, `revision`), also carried by supported Claude session cards and activity replies when a parent transcript is readable. `waiting` stays zero: no child permission source was verified. `complete` describes discovery coverage, independently of availability and count freshness: an older launch outside the parent window or a discovery cap can make the count partial without invalidating retained fresh evidence. Unsupported/missing sources remain unavailable at the child endpoint and have no card/activity summary, rather than verified zero. An empty available complete result is verified zero.

Native bindings are scoped by profile/root/project/host/socket. The reader uses the authorized root's listed native ID, with a socket-scoped live environment refresh at the existing 60-second cadence when a tmux session is present. It does not borrow the parent reply cache (whose legacy key is only the Deck ID). A changed listed native ID invalidates this binding immediately. Remote Claude transcripts are unavailable. No arbitrary task output path is followed.

S1 uses a conservative snapshot epoch: parent source changes (including append), restart or cache eviction may reset segment/cursors. Native invocation IDs and child tokens remain scoped internally; S2 must key UI navigation by root + segment + child + invocation. Historical segment lookup is deferred. Source rewrites are detected by file identity/size/mtime; unchanged-source caching assumes normal filesystem timestamp updates.

## Evidence and lifecycle

Only an Agent launch plus exact parent tool-result or metadata join establishes a linked child. Child files must corroborate their filename agent ID, native parent session and sidechain marker. `parentUuid:null` is valid and is never a cross-file join. Split response blocks keep the native parent block index. Metadata descriptions, prompts, tool arguments, outputs and reasoning are excluded from summary payloads; labels use bounded type/tool names.

An async result with `status:async_launched` or a recent child assistant record is provisional running evidence, valid for **30 seconds**. The result need not have an explicit background input. Missing/unreadable child files, stale running evidence and unlinked nonterminal children are unknown, never perpetual running. Metadata `finished:true` and a successful `SubagentHandback` with `toolEndsTurn:true` establish **finished**, not success; terminal metadata survives a missing parent launch and does not add to the Unknown count. Trusted structural task-notification attachments can supply succeeded/failed/canceled outcomes. Queue/prose copies are ignored; delivery IDs deduplicate notifications independently of invocation identities. A verified later invocation or child assistant activity can reopen the same child. Older terminal notifications cannot override that activity; a subsequent completion still closes it. The fleet footer and parent working state never supply child counts.

## Bounds and UI

- Shared cache: at most 128 root scopes, lazy idle eviction after 60 seconds, coarse reads no faster than every 6 seconds. All phones share ingestion; no follower goroutines or open file handles remain between reads.
- Each refresh first stats at most 201 directory entries. Unchanged sources reuse decoded summaries. Changed roots read at most a 2 MiB parent tail, 100 direct children, 32 KiB child identity head + 32 KiB action tail and 16 KiB metadata per child. No recursive discovery and no `History()` fan-out.
- At most 32 invocation edges per child. Parent-window/entry/edge limits mark discovery incomplete/truncated; malformed or partial records mark it incomplete. Normal child action-tail truncation changes neither coverage nor freshness. Files changing during reads degrade safely. Partial final JSONL lines wait for a later snapshot.
- Pages contain at most 50 children and approximately 128 KiB of child JSON plus the small envelope. Cursors include the root/profile/host/restart/segment/revision scope. File and directory symlinks below the verified parent are rejected; `os.Root` anchors reads and file identity checks catch replacement races.
- Cards announce a running count while evidence is available and unexpired, adding a partial hint when discovery coverage is incomplete. Local ticking expires cached badges even if networking stops. Idle parent replies remain visible.
- The sheet has a read-only, collapsible child list: last action, state, freshness and unavailable/unlinked explanations. It currently shows the first bounded page and labels additional results. Stable child IDs preserve row nodes, disclosure state and parent scroll across polling. Text is assigned with `textContent`. No child send, approve, stop or drill-in controls exist.
- Child polling stops while hidden and resumes on the normal 3-second visible cadence; only one request per open sheet is in flight. Poll failure visibly degrades freshness. No new SSE event is required: full polling snapshots recover after missed existing SSE events. Dedicated invalidations/incremental ingestion remain S4.

## Acceptance map and next slices

`subagents_test.go` covers async joins without a background flag, metadata-before-result, missing metadata, null chain parent, split blocks, handback, finished/unknown, duplicate completion, continuation, Monitor/Bash and legacy Task exclusion, ignored footer/prose, stale/disappeared children, nested/foreign identity exclusion, partial lines, limits, symlink escape, pages/byte ceilings, source rewrite/restart, multiple phones, scoped binding changes and authenticated root/profile/host rejection. `web/subagents.test.js` covers local expiration and lifecycle labels. `e2e/subagents.e2e.mjs` covers an idle parent, repeated malicious labels, stable row updates, disclosure/scroll preservation, read-only child DOM and hidden/resumed polling.

S2 needs launch anchors in a separate projection, historical-segment membership, stable native row/block IDs, a contained on-demand paged child transcript, read-only navigation and root/segment/child/invocation UI state. It must preserve existing parent delivery reconciliation and human/assistant filtering. S4 needs incremental ingestion and coalesced invalidations; slow SSE consumer tests belong there. OpenCode join/status/pagination/fork tests await the separate **2.x evidence gate**; no 1.x implementation is scheduled by this change.
